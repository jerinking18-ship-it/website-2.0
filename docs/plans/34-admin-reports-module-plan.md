# Admin Reports Module Plan

## Goal

Create a professional reports and analytics center inside the admin panel. The reports module should help the owner understand sales, orders, customers, inventory, delivery, coupons, support, and finance performance without needing external spreadsheets for everyday decisions.

This module should feel like a real business intelligence screen for a modern grocery ecommerce operation, not an empty statistics page.

## Recommended Tabs

- Overview
- Sales
- Orders
- Inventory
- Customers
- Delivery
- Promotions
- Support
- Finance

- Gross revenue
- Net revenue
- Total orders
- Average cart value

- COD revenue
- Online payment revenue
- Refund rate
- Cancellation rate

Useful actions:

- Filter by date range

- View revenue trend chart

## Date And Data Filters

The reports module should support:

- Today
- 7 days
- 30 days
- Quarter
- Custom date range
- Category filter
- Payment method filter
- Delivery zone filter
- Customer segment filter
- Coupon campaign filter
- Staff or delivery partner filter

## Export And Scheduling

The admin should be able to:

- Export reports as PDF
- Export reports as CSV
- Export reports as Excel
- Schedule daily reports by email
- Schedule weekly owner summary
- Download past generated reports
- See export status: Ready, Scheduled, Processing, or Failed

## Admin Actions

Important working actions:

- Refresh reports
- Reset filters
- Open detailed report view
- Export selected report
- Schedule email report
- Review insight
- Download generated report
- Cancel scheduled report

## Recommended Frontend Mock Version First

For the frontend mock, build:

- Reports sidebar item in admin panel
- Reports route at `/reports`
- Overview cards for key metrics
- Revenue trend chart using dummy data
- Report tabs for each report area
- Data tables for selected report type
- Insight cards with priority labels
- Export and schedule panel
- Working filters with dummy state
- Working buttons that update page state or show confirmation messages

## Future Backend Requirements

When backend work starts, reports should be powered by:

- CQRS read models for analytics
- Daily report aggregation jobs
- Order read database projections
- Inventory movement projections
- Customer behavior projections
- Coupon usage projections
- Delivery tracking projections
- Payment and settlement projections
- Export generation queue
- Scheduled email report queue

Recommended future endpoints:

- `GET /admin/reports/overview`

- `GET /admin/reports/finance`
- `POST /admin/reports/export`

## Design Direction

The reports page should look more premium than a basic dashboard:

- Clean executive-style cards
- Compact but readable tables
- Strong data hierarchy
- Soft secondary backgrounds
- Primary color for key actions and active states
- Clear chart sections
- Professional spacing
- No oversized empty cards
- No unnecessary decorative elements

## Priority For First Build

Build the mock in this order:

1. Add Reports route and sidebar item.
2. Add overview KPI cards.
3. Add sales/revenue chart.
4. Add report tabs and tables.
5. Add insights panel.
6. Add export and schedule report actions.
7. Make all buttons work with frontend dummy state.
